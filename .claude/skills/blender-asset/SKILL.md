# CampusCove Blender asset

Every game asset is **generated by a script** in `map-src/CampusCove/build_<thing>.py`. Only the `.py` files are
versioned; `out/`, `.blend` and raw `.glb` are git-ignored. Never hand-edit a mesh in Blender and export it:
a change that is not in a script is lost at the next rebuild.

Read `docs/ASSETS_STYLE_GUIDE.md` before modelling (style, budgets, interior contract, work buildings §8,
pond §9, fishing items §10). Premium rigged skins are separate: `front/scripts/skins/` (see its README).

## 1. Write the script

Start from the closest existing script (tool: `build_house_key.py`; building: `build_work_cafe.py` +
`build_work_cafe_ext.py`; whole area: `build_work_district.py`, `build_pond.py`). Header pattern:

```python
"""<What it builds>. Outputs: out/<category>/<key>/{model.glb,preview.png}. Then `npm run assets:optimize -- <category>`."""
if "__file__" not in globals():
    raise RuntimeError('Run with exec(open(p).read(), {"__file__": p}) so the script can find lib_common.py')
HERE = os.path.dirname(os.path.abspath(__file__))
sys.path.insert(0, HERE)
import lib_common as L
importlib.reload(L)          # pick up lib_common edits without restarting Blender
```

Use `lib_common.py` instead of raw bpy whenever it has the helper:

| Helper | Use |
|---|---|
| `new_build_scene(name)` | dedicated scene; the user's own scene is never touched |
| `b(gx, gz, h)` | **game coords → Blender**. Game is Y-up, -Z = north; Blender Z-up. Always think in game (x, z) |
| `make_mat(name, base, rough, pattern, var, accent=, emit=)` | painted procedural texture per material (no flat colours) |
| `box`, `cyl`, `cone`, `gable_roof`, `text_mesh`, `join`, `furn` | low-poly primitives, bevel + box UVs included |
| `wall(..., openings=, cols=)`, `interior_shell`, `walk_in_shell`, `perimeter`, `hinged_door` | walls with real door/window holes, walk-in buildings (`INTERIOR_FRONT_OUTER_Z`, `DOOR_OPENING`, `SHELL_GAP`) |
| `Collisions(coll).add("Name", ...)` | `COL_<Name>` boxes for the collision source |
| `check_grounded(objs, allow=L.ALLOW_INTERIOR)` | furniture must sit between y=0 and 3 cm (known "sunk furniture" bug, guide §6) — fail the build if it returns anything |
| `export_glb(path, objs)` | exports only `objs`, restores the user's selection |
| `snapshot(...)` / ortho camera (see `build_house_key.py`) | `preview.png` |
| `write_json` | `*.layout.json` (stations `station_<job>_NN`, spawn, doors) |

Rules the code depends on:
- Material prefixes: `IN_` interior, `EX_` exterior, `DC_` decor, `TW_` town, `IT_` item; building-specific
  materials carry the key (`IN_house_01_Sofa`).
- Interiors: metres, floor y=0, front door wall at z=+5, rooms toward -Z, node names `House_Floor_*`,
  `Door_Entrance*`, `Light_*`, `Window_*`, `Sky_*` (hidden in the open world via `hideNodes`).
- Walk-in exteriors keep a separate hinged `Door` node; the collision source must leave the doorway open.
- Collision: export `<name>.colsrc.glb` = visible objects + `cols.items`; never rely on auto collision.
- Budgets (triangles): furniture ~600, house exterior ~1 100, house interior ~5 200, work interior ≤12 000,
  work exterior ≤2 500, skin ≤30 000. Print the triangle count at the end of the script.
- Make it deterministic (fixed seeds) so a rerun reproduces the committed files.

## 2. Run it in Blender

Through the Blender MCP (Blender open with the add-on). Inspect first (`get_objects_summary`), then:

```python
p = r"C:\Users\Utilisateur\CampusCove\map-src\CampusCove\build_<thing>.py"
exec(open(p, encoding="utf-8").read(), {"__file__": p})
```

Look at the result before exporting decisions: `render_viewport_to_path` / `get_screenshot_of_window_as_image`
from the game's camera height (eye ≈ 1.6 m), and compare against `houses/house_01/preview.png` for style.
Lightmaps are headless (Cycles), Windows path:

```bash
"/c/Program Files/Blender Foundation/Blender 4.5/blender.exe" --background --factory-startup --python map-src/CampusCove/build_house_lightmaps.py -- work cafe
```

(Blender 5.2 is also installed; use the version the MCP session runs so outputs match.)

## 3. Optimize and wire

```bash
cd front && npm run assets:optimize -- <skins|decor|houses|town|work|park|items>
```

Draco + WebP (512 px skins/decor/items, 1024 buildings), `*.colsrc.glb` → `*.collision.json`, previews,
layouts and lightmaps copied. A new category or file kind that must keep its node names / second UV map needs a
rule in `front/scripts/optimize-assets.mjs` (`keepNodes`, `keepLightmapUvs`, `shipsAsIs`).

Then, depending on the asset:
- URL → `front/src/game/assets/catalog.ts` (typed key union + helper entry).
- Placement → `world.manifest.json` through the matching `front/scripts/apply-*.mjs` (idempotent), never by hand
  if a script owns that section.
- Sold / granted item → `item_defs` row (migration or `ShopSeeder`) with `preview_image` / `model_glb`
  pointing at `/assets/...` (skill `backend-game-data`).

## 4. Check

- `git status` shows the script **and** the optimized outputs; sizes are sane (`git diff --stat`).
- Skins: `cd front && npm run skins:check`.
- In game: press **C** in `/game` to toggle the collision debug overlay (skill `playtest-game`).
- Commit the script with its outputs in the same commit.
